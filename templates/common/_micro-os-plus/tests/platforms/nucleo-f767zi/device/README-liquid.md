This folder includes the **stm32f767xx** device definitions.

The result is a CMake interface library `micro-os-plus::device`.

Unlike the sibling nucleo-f767zi-cubemx platform, this one does not use
STM32CubeMX or the STM32F7xx HAL; the clock and the onboard LED are
brought up directly on the CMSIS registers (see
`include/micro-os-plus/stm32f767zi/system-clock.h` and
`../include/micro-os-plus/nucleo-f767zi/led-green.h`).

## stm32cubemx

Only `stm32cubemx/Drivers/CMSIS` was kept from the original
STM32CubeMX-generated project (register/bit-field definitions, no HAL);
everything else it once contained — `Core/`,
`Drivers/STM32F7xx_HAL_Driver/`, the generated CMake
(`cmake/stm32cubemx/CMakeLists.txt`, `CMakeLists.txt`,
`CMakePresets.json`), `.mxproject` and `startup_stm32f767xx.s` — was
removed once `src/hooks.cpp`/`src/system-stm32f767xx.cpp` took over
hardware bring-up, superseding the CubeMX-generated `main()`
(`HAL_Init()`/`SystemClock_Config()`/`MX_GPIO_Init()`) and
`system_stm32f7xx.c` (`SystemInit()`/`SystemCoreClockUpdate()`).
`stm32cubemx.ioc` was kept, as the record of the clock/pin
configuration `device/src/system-clock.cpp` and
`../src/led-green.cpp` reproduce on bare registers.

The `stm32cubemx` folder is therefore no longer CubeMX-managed; it is
not regenerated from the `.ioc` file, and any updates to the CMSIS
headers it holds have to be applied by hand.

## CMake

`device/CMakeLists.txt` defines the `micro-os-plus-device-interface`
library (`micro-os-plus::device`), which exposes the CMSIS include
directories kept under `stm32cubemx/Drivers/CMSIS`, the `STM32F767xx`
compile definition, and the sources below.

## `system-clock.cpp`

`device::system_clock` (declared in
`include/micro-os-plus/stm32f767zi/system-clock.h`), bringing up HSE,
in bypass mode, at the nominal 16 MHz the onboard ST-Link is documented
(in `stm32cubemx.ioc`'s `PH0/OSC_IN` pin assignment, `GPIO_Label` and
`RCC.HSE_VALUE`) to feed into `PH0/OSC_IN` — more accurate than the
internal HSI the CubeMX-generated `SystemClock_Config()` actually used,
at the same frequency; see the driver header for details. See
`src/hooks.cpp` for where it is instantiated and called.

## `vectors-stm32f767xx.c`

The file was added to replace the STM32CubeMX assembly file.

It can be generated from a CubeMX-generated `startup_stm32f767xx.s`
using the `convert-startup-to-vectors.mjs` script.

## `system-stm32f767xx.cpp`

Replaces the CubeMX-generated `system_stm32f7xx.c`. Declares
`SystemCoreClock` without an initialiser (so it lands in `.bss`, not
`.data`, avoiding it being overwritten by the `.data` copy that follows
`micro_os_plus_startup_initialise_hardware_early_hook()` in `_start()`;
see `src/hooks.cpp`), and implements `SystemInit()`/
`SystemCoreClockUpdate()` by reading the clock configuration back from
a `device::system_clock` instance.

## Memory map

The memory map was originally copied from `STM32F767xx_FLASH.ld` (part
of the removed STM32CubeMX project) into `device/linker-scripts/mem.ld`.

## SVD

For debugging purposes, the `STM32F767.svd` file was added locally.

It was generated by Claude from the file provided in the STM32F7xx_DFP
CMSIS Pack and the `armv7m-system-peripherals.svd` file available in
the `architecture-cortexm` package.
