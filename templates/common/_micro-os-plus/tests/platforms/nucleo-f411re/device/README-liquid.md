This folder includes the **stm32f411xe** device definitions.

The result is a CMake interface library `micro-os-plus::device`.

Unlike the sibling nucleo-f411re-cubemx platform, this one does not use
STM32CubeMX or the STM32F4xx HAL; the clock and the onboard LED are
brought up directly on the CMSIS registers (see
`include/micro-os-plus/stm32f411re/system-clock.h` and
`../include/micro-os-plus/nucleo-f411re/led-green.h`).

## stm32cubemx

Only `stm32cubemx/Drivers/CMSIS` was kept from the original
STM32CubeMX-generated project (register/bit-field definitions, no HAL);
everything else it once contained — `Core/`,
`Drivers/STM32F4xx_HAL_Driver/`, the generated CMake
(`cmake/stm32cubemx/CMakeLists.txt`, `CMakeLists.txt`,
`CMakePresets.json`), `stm32cubemx.ioc` and `startup_stm32f411xe.s` — was
removed once `src/hooks.cpp`/`src/system-stm32f411xe.cpp` took over
hardware bring-up, superseding the CubeMX-generated `main()`
(`HAL_Init()`/`SystemClock_Config()`/`MX_GPIO_Init()`) and
`system_stm32f4xx.c` (`SystemInit()`/`SystemCoreClockUpdate()`).

The `stm32cubemx` folder is therefore no longer CubeMX-managed; it is
not regenerated from a `.ioc` file, and any updates to the CMSIS headers
it holds have to be applied by hand.

## CMake

`device/CMakeLists.txt` defines the `micro-os-plus-device-interface`
library (`micro-os-plus::device`), which exposes the CMSIS include
directories kept under `stm32cubemx/Drivers/CMSIS`, the `STM32F411xE`
compile definition, and the sources below.

## `system-clock.cpp`

`device::system_clock` (declared in
`include/micro-os-plus/stm32f411re/system-clock.h`), bringing the
system clock up to 96 MHz (matching the sibling CubeMX platforms,
rather than this device's 100 MHz maximum), implemented directly on
the CMSIS `RCC`/`FLASH`/`PWR` registers; see `src/hooks.cpp` for where
it is instantiated and called.

## `vectors-stm32f411xe.c`

The file was added to replace the STM32CubeMX assembly file.

It can be generated from a CubeMX-generated `startup_stm32f411xe.s`
using the `convert-startup-to-vectors.mjs` script.

## `system-stm32f411xe.cpp`

Replaces the CubeMX-generated `system_stm32f4xx.c`. Declares
`SystemCoreClock` without an initialiser (so it lands in `.bss`, not
`.data`, avoiding it being overwritten by the `.data` copy that follows
`micro_os_plus_startup_initialise_hardware_early_hook()` in `_start()`;
see `src/hooks.cpp`), and implements `SystemInit()`/
`SystemCoreClockUpdate()` by reading the clock configuration back from
a `device::system_clock` instance.

## Memory map

The memory map was originally copied from `stm32f411xe_FLASH.ld` (part
of the removed STM32CubeMX project) into `device/linker-scripts/mem.ld`.

## SVD

For debugging purposes, the `STM32F411.svd` file was added locally.

It was generated by Claude from the file provided in the STM32F4xx_DFP
CMSIS Pack and the `armv7m-system-peripherals.svd` file available in
the `architecture-cortexm` package.
