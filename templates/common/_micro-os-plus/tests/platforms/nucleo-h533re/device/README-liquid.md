This folder includes the **stm32h533re** device definitions.

The result is a CMake interface library `micro-os-plus::device`.

Unlike the sibling nucleo-h533re-cubemx platform, this one does not use
STM32CubeMX, the STM32H5xx HAL, or the STM32H5xx Nucleo BSP; the clock
and the onboard LED are brought up directly on the CMSIS registers (see
`include/micro-os-plus/stm32h533re/system-clock.h` and
`../include/micro-os-plus/nucleo-h533re/led-green.h`).

## stm32cubemx

Only `stm32cubemx/Drivers/CMSIS` was kept from the original
STM32CubeMX-generated project (register/bit-field definitions, no HAL);
everything else it once contained — `Core/` (including `icache.c`,
whose `MX_ICACHE_Init()` enabled the instruction cache; this platform
leaves it disabled, unlike the sibling nucleo-h533re-cubemx one),
`Drivers/STM32H5xx_HAL_Driver/`, `Drivers/BSP/`, the generated CMake
(`cmake/stm32cubemx/CMakeLists.txt`, `CMakeLists.txt`,
`CMakePresets.json`), `.mxproject` and `startup_stm32h533xx.s` — was
removed once `src/hooks.cpp`/`src/system-stm32h533xx.cpp` took over
hardware bring-up, superseding the CubeMX-generated `main()`
(`HAL_Init()`/`SystemClock_Config()`/`MX_GPIO_Init()`/
`MX_ICACHE_Init()`/`BSP_LED_Init()`/`BSP_LED_On()`) and
`system_stm32h5xx.c` (`SystemInit()`/`SystemCoreClockUpdate()`).
`stm32cubemx.ioc` was kept, as the record of the clock/pin
configuration `device/src/system-clock.cpp` and
`../src/led-green.cpp` reproduce on bare registers.

The `stm32cubemx` folder is therefore no longer CubeMX-managed; it is
not regenerated from the `.ioc` file, and any updates to the CMSIS
headers it holds have to be applied by hand.

## CMake

`device/CMakeLists.txt` defines the `micro-os-plus-device-interface`
library (`micro-os-plus::device`), which exposes the CMSIS include
directories kept under `stm32cubemx/Drivers/CMSIS`, the `STM32H533xx`
compile definition, and the sources below.

## `system-clock.cpp`

`device::system_clock` (declared in
`include/micro-os-plus/stm32h533re/system-clock.h`), bringing up HSE
on the on-board 24 MHz X3 crystal and configuring PLL1 for a 250 MHz
SYSCLK/HCLK (the device's maximum), on the CMSIS `RCC`/`FLASH`/`PWR`
registers, matching the `stm32cubemx.ioc` configuration; see
`src/hooks.cpp` for where it is instantiated and called.

## `vectors-stm32h533xx.c`

The file was added to replace the STM32CubeMX assembly file.

It can be generated from a CubeMX-generated `startup_stm32h533xx.s`
using the `convert-startup-to-vectors.mjs` script.

## `system-stm32h533xx.cpp`

Replaces the CubeMX-generated `system_stm32h5xx.c`. Declares
`SystemCoreClock` without an initialiser (so it lands in `.bss`, not
`.data`, avoiding it being overwritten by the `.data` copy that follows
`micro_os_plus_startup_initialise_hardware_early_hook()` in `_start()`;
see `src/hooks.cpp`), and implements `SystemInit()`/
`SystemCoreClockUpdate()` by reading the clock configuration back from
a `device::system_clock` instance.

## Memory map

The memory map was originally copied from `STM32H533xx_FLASH.ld` and
`STM32H533xx_RAM.ld` (part of the removed STM32CubeMX project) into
`device/linker-scripts/mem.ld`.

## SVD

For debugging purposes, the `STM32H533.svd` file was added locally.

It was generated by Claude from the file provided in the STM32H533_DFP
CMSIS Pack and the `armv8m-mainline-system-peripherals.svd` file
available in the `architecture-cortexm` package.
