This folder contains the helper scripts used by the `tests` project to
build, run, and validate the test programs.

All scripts are generated from the templates in the
`@micro-os-plus/build-helper` package
(`templates/common/_micro-os-plus/tests/scripts/`) by the
`generate-tests-commons` action; do not edit them here, since the
changes will be overwritten at the next regeneration.

The `.mjs` scripts require Node.js and the npm dependencies of the
`tests` project (`json5`, `liquidjs`, `glob`, and the helper packages),
installed with `npm install` in the `tests` folder.
The `.sh` scripts require `bash`.

## `clear-build-folder.mjs`

Removes all the content of a build folder, except the `xpacks`
sub-folder, which holds the links to the binary tools installed by
`xpm`. This allows a full rebuild without the need to run
`xpm run link-dependencies` again.

Usage:

```sh
node scripts/clear-build-folder.mjs <build-folder>
```

The script fails if the argument is missing, if the path does not
exist, or if it is not a folder. Each removed entry is listed.

It is referred to by the `commandClearBuildFolder` property in
`package.json`, which is used by the `clear` action of each build
configuration.

## `compare-files.sh`

Compares the output of a test run (for example a TAP file) with a
reference file, and fails if they differ.

Usage:

```sh
bash scripts/compare-files.sh <actual> <expected>
```

Since some details are expected to vary between builds and platforms,
both files are normalised before comparison:

- lines starting with `Running:` or `Built with ` (optionally prefixed
  by `# `) are removed;
- hexadecimal pointers (`0x...`) and 16-digit hexadecimal values (as
  printed by mingw-gcc, without `0x`) are replaced by `0xXXX`;
- timings (`, time: N.N ms`) are removed;
- line numbers (`line: N`, `:N, `, and `:N)`) are replaced by `NNN`.

The differences, if any, are displayed in unified format (`diff -u`)
and the script exits with an error; otherwise it prints
`<actual> ok`.

In CMake builds, it is registered as a test by the
`add_compare_files_test()` function, defined in
`cmake/common-functions.cmake`:

```cmake
add_compare_files_test (
  NAME "unit-test-verbose-compare"
  DEPENDS "unit-test-verbose"
  FILES "${CMAKE_CURRENT_BINARY_DIR}/unit-test-verbose.tap"
        "${CMAKE_CURRENT_SOURCE_DIR}/assets/tap/unit-test.tap"
)
```

## `convert-startup-to-vectors.mjs`

Generates a µOS++ style `vectors-<device>.c` file from a CMSIS/HAL
`startup_<device>.s` assembly file, such as those generated by
STM32CubeMX.

Usage:

```sh
node scripts/convert-startup-to-vectors.mjs <startup_xxx.s> [vectors-xxx.c]
```

When the output file is omitted, the result is written to `stdout`,
and the diagnostic messages to `stderr`, so the output can be piped.

The script:

- locates the vector table, which starts at the `g_pfnVectors:` (or
  `IRQ_Vectors:`) label and consists of consecutive `.word <symbol>`
  lines; blank lines and comment lines are ignored, and the first
  other line ends the table;
- preserves the trailing comments (`@ ...`, `// ...`, or `/* ... */`)
  of the `.word` lines, to be used as comments in the C file;
- detects the architecture from the core exception slots: a reserved
  `MemManage_Handler` slot means ARMv6-M (Cortex-M0/M0+), and a used
  `SecureFault_Handler` slot means ARMv8-M;
- skips the first 16 entries (the initial stack pointer,
  `Reset_Handler`, and the core exceptions), which are fixed by the
  architecture;
- renders the remaining device specific IRQ handlers with the
  `templates/vectors-liquid.c` Liquid template.

The `convert-vectors` action in `package.json` runs it for all
platforms that use STM32CubeMX startup files, for example:

```sh
node scripts/convert-startup-to-vectors.mjs \
  platforms/nucleo-f411re/device/stm32cubemx/startup_stm32f411xe.s \
  platforms/nucleo-f411re/device/src/vectors-stm32f411xe.c
```

## `get-libraries-paths.mjs`

Asks the compiler for the locations of its run-time libraries
(`libstdc++`, `libc++`, and the compiler run-time), and prints them on
`stdout` as a colon-separated list, without a trailing new line.
The native builds pass these paths to the linker as `-rpath` and `-L`
options, so that the test programs use the libraries that come with
the compiler, not those installed in the system.

Usage:

```sh
node scripts/get-libraries-paths.mjs clang++|g++ [options...]
```

The first argument is the compiler; the optional extra arguments are
passed to the compiler in each query.

The method depends on the compiler and the host:

- clang on GNU/Linux: the folder of `libc++.so` and the output of
  `-print-runtime-dir`;
- clang on macOS: the folder of the first `libc++.dylib` found below the
  `lib` folder of the toolchain (if any), and the folder of the
  `-print-libgcc-file-name` library;
- gcc on GNU/Linux and macOS: the folder of `libstdc++.a`.

Other platforms are not supported (Windows builds use `-static`). For
compilers that are neither clang nor gcc, the output is empty.

Although CMake can run sequences of piped commands, meson cannot, and
requires an external script; for consistency, both use this script.

In CMake (`platforms/native/CMakeLists.txt`):

```cmake
# Compute RPATH; return result in `rpath_options_list`.
if (CMAKE_SYSTEM_NAME STREQUAL "Linux" OR CMAKE_SYSTEM_NAME STREQUAL "Darwin")
  # On non-Windows, get the actual libraries paths by asking the compiler.
  execute_process (
    COMMAND node "${CMAKE_SOURCE_DIR}/scripts/get-libraries-paths.mjs"
            ${CMAKE_CXX_COMPILER}
    OUTPUT_VARIABLE cxx_library_path
    OUTPUT_STRIP_TRAILING_WHITESPACE
  )

  set (rpath_options_list)

  if (NOT "${cxx_library_path}" STREQUAL "")
    string (REPLACE ":" ";" cxx_library_path_list ${cxx_library_path})

    cmake_path (GET CMAKE_CXX_COMPILER FILENAME cxx_filename)
    message (STATUS "${cxx_filename} RPATH_LIST: ${cxx_library_path}")

    foreach (RPATH IN LISTS cxx_library_path_list)
      cmake_path (SET normalized_path NORMALIZE ${RPATH})
      list (APPEND rpath_options_list "-Wl,-rpath,${normalized_path}")
      list (APPEND rpath_options_list "-L${normalized_path}")
    endforeach ()
  endif ()
endif ()
```

In meson, the script is called with `run_command()` from
`platforms/native/meson.build`.

## `show-coverage.sh`

Displays the code coverage of a test program, using the LLVM
`llvm-profdata` and `llvm-cov` tools. Since the tools are invoked via
`xcrun`, it is currently available only on macOS.

Usage:

```sh
bash scripts/show-coverage.sh <binary> <prof-name> [<sources>]
```

The script:

- merges `<prof-name>.profraw` (the raw profile written by the test
  program, as set by `LLVM_PROFILE_FILE`) into `<prof-name>.profdata`;
- shows the annotated sources (line, region, branch, instantiation, and
  MC/DC counts), filtering out the comment lines, the blank lines, the
  separators, and the fully covered branches, to keep the report short;
- shows the summary report.

The files in `xpacks` and `tests` folders are excluded. The optional
third argument limits the report to a single source file, for example
`../../../../src/doubly-list-links.cpp` (relative to the build folder).

In CMake builds, when `XPACK_ENABLE_COVERAGE` is enabled, it is
registered as a test that depends on the test program run, for
example in `platforms/native/cmake/artefacts.cmake`.

## `xcdl-export.mjs`

Generates the `CMakeLists.txt` and `meson.build` files from the
`xcdl-*.jsonc` metadata files, using the `templates/CMakeLists-liquid.txt`
and `templates/meson-liquid.build` Liquid templates. The results are
written next to each input file.

Usage:

```sh
node scripts/xcdl-export.mjs <xcdl-package.jsonc> [<xcdl-package.jsonc>...]
```

The input files are parsed as JSON5 (comments and trailing commas are
accepted). The substitution is performed by the `substitute()` function
from `@xpack/npm-packages-helper`, which must be installed in
`tests/node_modules`.

The `xcdl-export` action in `package.json` runs it for all test
sources:

```sh
node scripts/xcdl-export.mjs sources/*/xcdl-*.jsonc
```
